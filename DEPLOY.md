# Деплой «КАДР» — из Git сразу на стенд

Проект собирается в **один самодостаточный файл** `dist/index.html`
(весь JS и CSS заинлинены, внешний хост не нужен — только статика).
Поэтому любой хостинг, который умеет «импорт из Git», подходит.

Ниже — три проверенных способа. Выберите один.

---

## 0. Сначала: ключи БД (если подключаете Supabase)

Создайте файл `.env.production` в корне (рядом с `package.json`) по образцу
`.env.example` и впишите ключи из Supabase (Settings → API):

```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=ваш-anon-ключ
```

Закоммитьте `.env.production` вместе с проектом — сборка подхватит его
автоматически на любой платформе. (anon-ключ публичный по дизайну Supabase,
доступ к данным защищён RLS-политиками, коммитить его безопасно.)

Если файл не создавать — сайт соберётся в локальном режиме (данные в
localStorage браузера), всё будет работать.

---

## 1. Netlify  (рекомендуем — проще всего)

1. [app.netlify.com](https://app.netlify.com) → **Add new site → Import an existing project**.
2. Выберите ваш Git-репозиторий.
3. Netlify сам увидит `netlify.toml`: команда `npm run build`, публикация `dist`.
4. Нажмите **Deploy**. Через ~1 минуту сайт онлайн.

Дальше каждый `git push` в основную ветку автоматически пересобирает и
обновляет стенд.

## 2. Vercel

1. [vercel.com](https://vercel.com) → **Add New… → Project** → импорт репозитория.
2. Vercel подхватит `vercel.json` (сборка `npm run build`, папка `dist`).
3. **Deploy**.

Автодеплой на каждый пуш включён по умолчанию.

## 3. GitHub Pages  (если сайт на github.io)

Всё уже настроено в `.github/workflows/deploy.yml`:

1. Запушьте проект в ветку `main` (или `master`).
2. В репозитории: **Settings → Pages → Source → «GitHub Actions»**.
3. Во вкладке **Actions** дождитесь завершения «Deploy to GitHub Pages».
4. Сайт появится на `https://<логин>.github.io/<репо>/`.

Ключи БД для этого пути задаются в **Settings → Secrets and variables →
Actions** (секреты `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`) —
workflow уже прокидывает их в сборку. Либо просто закоммитьте `.env.production`.

---

## Проверка, что всё хорошо

- Откройте сайт. В тулбаре справа горит бейдж:
  **«БД: облако»** (зелёный) — подключён Supabase, или
  **«БД: локально»** — данные в браузере.
- Зарегистрируйтесь / войдите. Если бейдж «облако» — аккаунт создан в БД.

## Если сайт показывает ошибку или пустую страницу

Почти всегда причина одна: хостинг публикует **корень репозитория**, а не
папку `dist`. Убедитесь, что в настройках деплоя:

- Build command: `npm run build`
- Publish / Output directory: `dist`

Файлы `netlify.toml` / `vercel.json` / GitHub Actions уже содержат эти
значения, поэтому при импорте из Git ничего настраивать вручную не нужно.
