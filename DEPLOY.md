# Деплой «КАДР» на reg.ru (kadr-scr.ru)

Проект собирается в **один самодостаточный файл** `dist/index.html`
(весь JS и CSS заинлинены). На хостинге reg.ru его раздаёт обычный Apache —
внешний Node-хост не нужен. Бэкенд (регистрация, аккаунты, БД) — это
небольшой **PHP-API** (папка `api/`) + **MySQL** на том же хостинге.

Актуальный workflow: **`.github/workflows/deploy-regru.yml`** (остальные
конфиги деплоя удалены как неиспользуемые).

---

## Почему раньше была ошибка «module script MIME type»

reg.ru «Сайт из Git» выкладывает **корень той ветки, к которой подключён**.
Была подключена ветка `main` — а в ней лежит исходный код (`src/main.tsx`),
а не сборка. reg.ru отдал исходный `index.html` со ссылкой на `/src/main.tsx`
→ браузер получил его с пустым MIME-типом → ошибка.

**Правильно: подключить reg.ru к ветке `deploy`**, в которой лежит только
сборка. GitHub Actions создаёт и обновляет её автоматически при каждом пуше.

---

## ПУТЬ A — reg.ru «Сайт из Git» + ветка `deploy`  (рекомендуем)

1. Запушьте изменения в `main` (или запустите Actions → «Deploy to reg.ru» → Run workflow).
2. Дождитесь, пока workflow создаст/обновит ветку **`deploy`**
   (в репозитории появится ветка `deploy` со сборкой и папкой `api/`).
3. В панели reg.ru: **Сайт из Git** → ваш репозиторий → в поле «Ветка»
   укажите **`deploy`** (вместо `main`/`master`). Сохраните.
4. Reg.ru выложит содержимое ветки `deploy` — и сайт заработает.
   Каждый следующий `git push` в `main` обновляет ветку `deploy`, а reg.ru её подхватывает.

## ПУТЬ B — FTP через GitHub Actions  (альтернатива)

Сборку делает GitHub Actions, готовый сайт загружается на хостинг по **FTP**.

1. В панели reg.ru → **«FTP»** возьмите адрес сервера, логин и пароль.
   Папка сайта — `/www/kadr-scr.ru/`.
2. В GitHub: Settings → Secrets and variables → Actions → добавьте секреты
   `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`, `FTP_TARGET_DIR` (со слешем!).
3. Запушьте в `main` — workflow загрузит сборку по FTP (с очисткой папки).

# БД на reg.ru (MySQL + PHP-API)

Сайт — чистый фронтенд, поэтому к MySQL он ходит через **PHP-API** (папка
`api/`). Он раскладывается на сервер вместе со сборкой и работает на том же
домене (`https://kadr-scr.ru/api/...`) — CORS не нужен.
Режим включается переменной `VITE_BACKEND=regapi` (в workflow уже прописано
по умолчанию и имеет приоритет над Supabase).

**Шаг 1. Создайте базу данных в reg.ru**
Панель → **«Базы данных»** → «Создать базу». Запомните: имя БД, пользователя и
пароль. Хост — почти всегда `localhost`.

**Шаг 2. Примените схему**
Там же → **phpMyAdmin** → выберите созданную БД → вкладка **SQL** → вставьте
содержимое файла [`mysql/schema.sql`](./mysql/schema.sql) → «Вперёд».
Создадутся таблицы `kadr_accounts`, `kadr_users`, `kadr_sessions`,
`kadr_account_state`.

**Шаг 3. Заполните реквизиты**
Откройте [`api/config.php`](./api/config.php) и впишите `db_name`, `db_user`,
`db_pass` из шага 1. Закоммитьте файл (репозиторий держите **приватным** —
пароль БД лежит в этом файле, но на сервер он попадает при каждом деплое).

**Шаг 4. Запушьте**
```bash
git add . && git commit -m "db: подключаем MySQL на reg.ru" && git push
```
Workflow соберёт фронтенд с `VITE_BACKEND=regapi`, скопирует `api/` и выложит
всё на сервер (ветка `deploy` / FTP).

**Проверка:** откройте `https://kadr-scr.ru/api/state.php` — без токена вернёт
`{"ok":false,...}` с кодом 401 (это норма: PHP и MySQL отвечают). Затем
зарегистрируйтесь на сайте — в тулбаре появится бейдж **«БД reg.ru»**.

## Важные нюансы

- **Регистрация и вход** обрабатываются PHP: пароль — только bcrypt-хеш
  (`password_hash`), сессия — случайный токен с временем жизни.
- **Доступ к данным** — у каждого пользователя только к своему рабочему месту
  (все запросы проверяют токен и `account_id`).
- Служебные файлы `config.php`, `db.php`, `common.php` закрыты от прямого
  доступа по URL (`api/.htaccess`).

## Структура файлов БД

```
api/                  # PHP-API (раскладывается в dist/api/ при сборке)
  config.php          # реквизиты MySQL — ЗАПОЛНИТЬ
  db.php, common.php  # подключение и помощники
  register/login/restore/logout/state/users.php  # эндпоинты
  .htaccess           # закрывает служебные файлы
mysql/schema.sql      # схема — применить в phpMyAdmin
src/backend/regapi.ts # фронтенд-адаптер (режим regapi)
```

## Если сайт показывает ошибку или пустую страницу

Почти всегда причина одна: хостинг публикует **корень репозитория**, а не
сборку. Убедитесь, что reg.ru подключён к ветке **`deploy`**, а не к `main`,
и что workflow отработал успешно (зелёная галочка во вкладке Actions).
